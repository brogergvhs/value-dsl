Values represent human motivational priorities based on [Schwartz value theory](https://en.wikipedia.org/wiki/Theory_of_Basic_Human_Values). The DSL ships with **30 built-in values** organized on a circular model — the farther apart two values are on the circle, the more they conflict.

## The Schwartz Circle

Values are positioned on a unit circle using polar coordinates `(angle, radius)`. The circle is divided into **10 categories**, each representing a cluster of related motivations:

| Category         | Angle (rad) | Description                                     |
| ---------------- | ----------- | ----------------------------------------------- |
| `power`          | 0.00        | social status, control, and authority           |
| `achievement`    | 0.63        | success, competence, and influence              |
| `hedonism`       | 1.26        | pleasure, enjoyment, and comfort                |
| `stimulation`    | 1.88        | novelty, excitement, and challenge              |
| `self_direction` | 2.51        | autonomy, creativity, and privacy               |
| `universalism`   | 3.14        | justice, equality, and broad concern for others |
| `benevolence`    | 3.77        | care, loyalty, and helpfulness                  |
| `tradition`      | 4.40        | devotion, humility, and respect for customs     |
| `conformity`     | 5.03        | obedience, discipline, and politeness           |
| `security`       | 5.65        | safety, stability, and order                    |

Values at opposite ends of the circle (angular distance ≈ π) produce the highest conflict scores. For example, `self_direction` (autonomy, angle ≈ 2.51) and `conformity` (obedience, angle ≈ 5.03) are near-opposites.

## Custom Values

Declare a custom value with explicit polar coordinates:

```text
value name = <angle>, <radius>
```

```text
// Custom value with geometry
value data_sovereignty = 2.04, 0.92
‎
// Multiple custom values (dense group — no blank line needed)
value trust = 1.57, 0.85
value accountability = 3.20, 0.80
```

The **category** is derived automatically from the angle — the value is assigned to whichever Schwartz category in the bounds of which the angle lays.
The **category** itself is not used anywhere except UIs (e.g. when using LSP Hover) and is just a conveniece inference for ease of value tracking.

### Geometry Constraints

| Field  | Valid Range                 | Error if violated            |
| ------ | --------------------------- | ---------------------------- |
| angle  | `[0, 2π)` → `[0, 6.283...)` | `value.angle.out_of_bounds`  |
| radius | `[0, 1]`                    | `value.radius.out_of_bounds` |

### Validation Rules

| Condition                                                | Severity | Code                       |
| -------------------------------------------------------- | -------- | -------------------------- |
| `angle` and `radius` exactly match a built-in's geometry | Warning  | `value.builtin.match`      |
| Name matches a built-in value                            | Error    | `value.builtin.conflict`   |
| Name declared more than once                             | Error    | `value.duplicate`          |
| Referenced in assignment but not declared or built-in    | Error    | `assignment.value.unknown` |
