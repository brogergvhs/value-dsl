The LSP server provides IDE integration for `.dsl` files. It runs as a separate process and communicates over stdio using the Language Server Protocol.

```bash
make lsp         # → ./bin/dsl-lsp
make build-full  # → ./bin/dsl-full, runs as `dsl-full lsp`
```

Use `dsl-lsp` directly, or configure an editor to run `dsl-full` with `lsp`
as its first argument.

For a combined binary literally named `dsl`, run
`make build-full FULL_BIN=./bin/dsl` and configure the editor command as
`dsl lsp`.

Docker is also supported for devcontainer or remote-editor setups:

```bash
make docker-build
docker run --rm -i -v "$PWD:/workspace" -w /workspace value-dsl:local /usr/local/bin/dsl-lsp
```

For local editors, the native `dsl-lsp` binary is usually simpler because file
paths do not need to cross a container boundary.

## Workspace awareness

When a `.dsl` file is below a directory containing `main.dsl`, the LSP analyzes it against that workspace. Hover, completion, go to definition, references, rename, diagnostics, and semantic tokens can use declarations from sibling files.

Standalone files, including `*_lone.dsl` and files inside `_lone/`, are analyzed by themselves.

See [Workspaces](/docs/workspace) for the exact loading rules.

## Feature Details

### Hover

Shows documentation when hovering over a symbol:

| Symbol kind    | Hover content                                                            |
| -------------- | ------------------------------------------------------------------------ |
| Built-in value | Category, angle, radius                                                  |
| Custom value   | Derived category, angle, radius (or "invalid" if geometry is incomplete) |
| Stakeholder    | Which requirements and assignments reference it                          |
| Requirement    | Context clauses, action, stakeholders list, metadata, traceability links |
| Clause keyword | Purpose of the clause and valid values                                   |

### Completion

Context-aware suggestions at any cursor position:

| Context          | Suggestions                                                                |
| ---------------- | -------------------------------------------------------------------------- |
| Top-level        | `stakeholder`, `value`, `requirement`, `assignment`                        |
| Requirement body | Clause keywords, action verbs, declared stakeholder names, priority levels |
| Assignment body  | Declared stakeholder names, value names (built-in + custom)                |

Completion items for values include their category and geometry as documentation.

### Go to Definition

`textDocument/definition` — jumps to the declaration of the symbol under the cursor. Works for stakeholders, values, and requirements, including declarations in sibling workspace files.

### Go to Declaration

`textDocument/declaration` — reuses `textDocument/definition`. In this DSL,
declarations and definitions are the same source location.

### Find References

`textDocument/references` — lists all locations where the symbol under the cursor is used across the workspace.

### Document Highlight

`textDocument/documentHighlight` — highlights the declaration and references of
the symbol under the cursor in the current document.

### Rename

`textDocument/rename` — renames a symbol and all its references simultaneously.

Rename validates:

- New name must be a valid identifier
- New name must not be a reserved keyword
- New name must not conflict with an existing declaration

Validation errors are reported to the editor as a user-visible message.

### Code Actions

`textDocument/codeAction` — returns quick fixes as workspace edits. Code actions
use the same workspace analysis as diagnostics, so edits can target closed
sibling `.dsl` files when the current file belongs to a `main.dsl` workspace.

| Code action                                            | Edit                                                                                  |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| Add missing stakeholders                               | Inserts missing `stakeholder <name>` declarations after the existing stakeholder list |
| Remove duplicate builtin value `<name>`                | Deletes a custom value declaration that has the same name as a built-in value         |
| Replace duplicate value `<name>` with builtin `<name>` | Deletes a custom value with built-in geometry and rewrites its references             |
| Add assignment block for current requirement           | Inserts or completes the assignment block for the requirement under the cursor        |
| Add missing assignment blocks                          | Inserts or completes assignment blocks for all requirements in the workspace          |

Generated assignment entries are prefilled as `<stakeholder> -> ` and leave the
value side empty.

### Document Symbols

`textDocument/documentSymbol` — populates the editor's outline/symbol panel:

| Symbol                                       | LSP kind |
| -------------------------------------------- | -------- |
| Stakeholder declaration                      | Variable |
| Value declaration                            | Constant |
| Requirement declaration                      | Object   |
| Requirement child (clause, action, metadata) | Property |

### Document Links

`textDocument/documentLink` — makes URL-like `linked_to` targets clickable.
Bare host-like targets such as `google.com/search?q=lsp` are linked as HTTPS
URLs.

### Workspace Symbols

`workspace/symbol` — searches declarations known to the LSP server from open
documents. If an open file belongs to a `main.dsl` workspace, results can
include declarations from sibling workspace files.

### Folding Ranges

`textDocument/foldingRange` — folds contiguous stakeholder declarations,
contiguous value declarations, and each requirement or assignment block.

### Selection Ranges

`textDocument/selectionRange` — expands from the token under the cursor to the
same enclosing declaration group or requirement/assignment block used by folding
ranges.

### Linked Editing

`textDocument/linkedEditingRange` — links same-document requirement IDs and
their assignment header references while editing. The server returns the ranges;
the editor decides whether to mirror typed edits. VS Code supports this when
linked editing is enabled. Neovim's built-in LSP client does not currently apply
the mirrored edit automatically, so use rename there.

### Formatting

`textDocument/formatting` — formats the whole document using the same formatter
as the CLI.

`textDocument/rangeFormatting` — formats the selected source lines as a DSL
fragment and returns an edit limited to those lines.

### Diagnostics

Published automatically on open and after document changes, debounced by the
LSP debounce setting. The server sends `textDocument/publishDiagnostics` after
each analysis run. Diagnostics map directly to the
[validation codes](/docs/validation).

For workspaces, diagnostics are published per source file. Open buffers are
used instead of their on-disk contents, and closed sibling files still receive
diagnostics when workspace analysis runs.

The server also handles `workspace/didChangeWatchedFiles` for `.dsl` files.
When the client sends file create/change/delete events, the server invalidates
closed-file cache entries, clears diagnostics for deleted files, and schedules
workspace analysis. VS Code sends these events through the repository extension.
Other editors only get closed-file updates for external file changes if their
LSP client sends `workspace/didChangeWatchedFiles`.

### Semantic Tokens

`textDocument/semanticTokens/full` — provides structured token roles for syntax highlighting independent of tree-sitter:

| Token type   | Modifiers        | Meaning                            |
| ------------ | ---------------- | ---------------------------------- |
| `type`       | `declaration`    | Stakeholder declaration            |
| `type`       | —                | Stakeholder reference              |
| `enumMember` | `declaration`    | Custom value declaration           |
| `enumMember` | —                | Custom value reference             |
| `enumMember` | `defaultLibrary` | Built-in value reference           |
| `function`   | `declaration`    | Requirement/assignment declaration |
| `function`   | —                | Requirement/assignment reference   |
